# 外部试用清单

本清单用于 v0.1.0 发布前由 2–5 名未参与实现的使用者执行。不得在记录中收集真实
凭据、原始会话内容或个人路径；问题附件先运行 `reprocore redact --check`。

## 参与者任务

1. 在 Windows 或 macOS/Linux 上按安装文档安装 tarball。
2. 运行 `reprocore doctor`，说明每个检查结果是否易懂。
3. 使用合成 fixture 创建 Oracle，并完成 3/3 replay。
4. 执行 minimize，确认 proof 能区分 `oneMinimal` 与 `budgetExhausted`。
5. 尝试不带 `--confirm-export` 的 pack，确认被阻断且没有产物。
6. 确认导出后运行 verify 5/5，并在断网状态打开 HTML 报告。
7. 对带测试 token 的文本与未知二进制附件运行 `redact --check`。

## 记录模板

| 字段                     | 内容               |
| ------------------------ | ------------------ |
| 匿名参与者编号           | T1–T5              |
| 操作系统与 Node 版本     | 不含用户名或设备名 |
| 是否独立完成安装         | 是/否              |
| 是否独立完成最小化与验证 | 是/否              |
| 安全阻断是否清楚         | 1–5                |
| 报告是否足以复现         | 1–5                |
| 首个阻塞点               | 去敏描述           |
| 建议                     | 去敏描述           |

## 发布通过条件

- 至少 2 名参与者完成；目标 5 名。
- 每人都能识别 `--confirm-export` 的意义。
- 没有 P0/P1 安全问题或无法完成的共同阻塞。
- 文档导致的问题在发布提交前修复并重新验证。

填写后的结果应汇总为不含个人信息的 Issue 或发布检查记录。没有真实参与者签字时，
不得把自动化测试描述为“已完成外部试用”。
